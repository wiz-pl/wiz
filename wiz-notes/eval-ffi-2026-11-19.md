# Lifting the interpreter's FFI restriction (`#eval` and externs)

**Status:** exploration + prototype, 2026-11-19. Branch `eval-ffi`, worktree
`/workspace/wt/eval-ffi`. No PR (branch only). The prototype is the smallest change
that makes a real `#eval` of an `Array` operation return a value instead of panicking
`foreign functions only run in compiled code (wiz run)`.

**One-line result.** `#eval` is already not uniformly blocked: 78 of the 210 `extern`
declarations in `lib/` have an interpreter path today (68 through a Wiz model behind
`implemented_by`, 10 through the Lean `Bytes` model). The panic survives for 132, of
which 33 are **pure** (`Array`, `Str`, `StrMap`, `UInt64`, `Float64`) and 99 are
effectful. The pure 33 are the target; this note adds `Array` to the existing Lean-side
bridge and shows the model agrees with C on the `natives` differential shape.

## 1. Why the panic happens (the path, precisely)

`#eval e` in `Wiz/Elab/Command.lean` (`command.eval`) elaborates and erases `e`, then
calls `compileReachableE … (externImpls := false)` (`Wiz/Compiler/Run.lean`), runs the
erased term with `run`, and reads the value back with `readback`.

* For a **definition** `f` with `attribute [implemented_by g] f`, erasure with
  `externImpls := false` keeps `f`'s own body and ignores `g` (master `Run.lean:690`–`710`).
  The kernel, `#eval`, and `#run` all use the model; compiled code uses `g`. This is
  stage 22b, and it is the mechanism `Word`, `WordArray`, `WordMap` and `Intern` use.
* For an **`extern`** there is no body. The declaration is registered as a `builtin`
  with a key `extern:cname:kinds:result:io:header:finalizer`; `compileReachableE`
  turns it into `.prim .unreachable #[.global key]` (master `Run.lean:717`). At run time
  `fireNative` dispatches the C name through the two hand-written tables
  (`bytesNative?` and one `wiz_nat_show` case); anything else reaches
  `panic! s!"{op}: foreign functions only run in compiled code (wiz run)"`.
  `#run` has the same table duplicated in `IRRun.lean` (`nativeOp`).

So the restriction is not in `Wiz/Core/Eval.lean` (the kernel's NbE evaluator has no
extern case at all: an axiom is a neutral). It is the **runtime table of
`Wiz/Compiler/Run.lean` + `IRRun.lean`**. The brief's phrasing ("Eval.lean, the extern
case") points at the wrong file in this tree; the message is identical.

## 2. Reachability count (measured on `master` `c2efe881`)

`lib/` has 118 modules; 12 declare `extern`s. Counting the declarations:

|---|---:|---|

| **no model** | **132** | |
| — pure value ops | **33** | `Std` 17 (`Array` 5, `Str` 8, `StrMap` 4), `IO` 16 (`UInt64` 9, `Float64` 7) |
| — effectful / sys / handles | **99** | `Sys` 66, `MVar` 10, `Serial` 7, `IO` 5, `Ref` 4, `Session` 4, `Handle` 2, `Std` 1 |

The modules *containing* unmodelled externs are 8 of 118: `Std`, `IO`, `Sys`, `MVar`,
`Ref`, `Serial`, `Session`, `Handle`. Only two of those have **pure** blocked ops
(`Std`, `IO`). Definition-level, the pure blocked surface is concentrated too:
signatures mentioning `Array`/`Str`/`StrMap`/`UInt64`/`Float64` occur in `Std` (8),
`IO` (16) and `Hdl/Sim.wiz` (14 `Array` uses: its whole fast simulator is
compiled-only, `lib/Hdl/Sim.wiz:22`).

Transitively, 42/118 modules import one of those 8, but almost all for `IO` effects;
that is a different restriction (effects cannot be *run* by `#eval`, and no pure model
would change that).

## 3. The option table

| option | mechanism | what it buys | soundness obligation | cost |
|---|---|---|---|---|
| **3. Wiz model** (reverse `implemented_by`) | an `extern` gets a pure Wiz `model`/`interp` body; `compileReachableE (externImpls := false)` substitutes it. For a type, the surface must be an inductive with a model (as `WordArray`'s sealed `mk (List …)`), not an axiom. | model is Wiz, checkable/provable; kernel, `#eval`, `#run` and compiled code can all be compared; `#print axioms` shows the trust. | differential test model vs native (the `natives` group), exactly as 22b: a model is trusted, not proved equal. | parser/elaborator + `Globals` + `compileReachableE` plumbing; a model type and conversions for `Array` (the runtime's `Array` is a native RC buffer, so `mk`/`toList` are O(n) or a new native representation); `Float64` needs a real Wiz float type. Medium/large. |
| **4. Compile on demand** | at an extern, emit the erased/IR program for the (closed) `#eval` expression to a temp dir through the existing C/LLVM backend, run it, parse the printed result into a term. | exact native semantics for *every* extern, including effects; no per-op model; reuses `Build.runGlobal`. | the C runtime is already trusted; the new obligations are purity (must refuse IO/effectful results), determinism, sandboxing, and cache keys (source + runtime + compiler). | small prototype, hard value boundary: only printable/structural results marshal; functions, closures and foreign pointers do not. Breaks the "pure elaborator": checking now needs a C toolchain and a subprocess (`Wiz/Smt/Process.lean` is the precedent, behind `opaque`, for tactics — not for `#eval`). Seconds per query; bad for the matrix's ~3 700 cells. |
| **5. Interpreter FFI bridge** | a Lean-side table of pure externs, keyed by the C name, over interpreter values (`RVal`/`IVal`); `fireNative` calls it before panicking. This is what `BytesModel` (21ag) already is. | `#eval` and `#run` work for the pure surface with no compiler, no subprocess, no new syntax; values stay in the interpreter; small and local. | hand-written model must agree with `runtime/`; obligation is the existing differential harness (`natives`: `#eval`, `#run`, C, LLVM), extended to the new type. Effects stay panics. | per-op Lean code; duplicates the semantics (two models: Lean and Wiz if option 3 is added later); `readback` needs a value form. `Float64` is the hard case (rounding, NaN, signed zero, `%.17g` formatting). **Chosen for the prototype.** |

**Verdict.** Option 3 is the principled long-term shape for *pure values*: it makes the
model part of the language, so proofs and the kernel see it, and it is the mechanism the
repo already uses wherever the surface is an inductive. It is not small for `Array`,
because `Array` is an `axiom` over a native RC buffer: a Wiz model first needs the
surface to become an inductive with a native representation (22d), plus O(n)
conversions or a new native representation. Option 4 is the only option that reaches
effects and arbitrary externs, but its value boundary (what can be marshalled back) is
exactly the hard part, and it trades a pure elaborator for a compiler dependency.
Option 5 is the cheapest honest step and is already the house style for `Bytes`; it is
what the prototype does.

## 4. Prototype: `Array` in the interpreter bridge

### What changed

* `Wiz/Compiler/Run.lean` (`#eval`'s interpreter):
  * a new value form `RVal.arr : Array RVal` (the `Bytes` value form is the precedent);
  * `ArrayModel.getD`/`ArrayModel.set`, the pure model of `runtime/rt_data.inc`'s
    `wiz_array_get`/`wiz_array_set` (copy on `set`; out of range: default / unchanged);
  * `arrayNative?`, the table for `wiz_array_empty/push/size/get/set`, called from
    `fireNative` before the panic (the zero-arity `Array.empty` is reached through the
    erased type argument, so it is the same path);
  * `readback` prints an `Array` value as `[a, b, c]` (element type from the `Array`'s
    application spine);
  * **argument indexing follows the erased representation**: an implicit type parameter
    is still an application argument, passed as `◾` (`Command.lean`'s `extern` comment:
    "erased parameters are passed as ◾ and ignored"; `C.lean`'s wrapper takes one
    `wiz_val` per parameter and skips `e`, and `Wasm.lean` zips the actual arguments
    with `sig.params`). `RVal.nativeArity` already counted them, correctly; the model
    therefore does not read `args[0]`, but the positions `ExternSig.argIndices` gives
    after skipping `e`. The `master` panic message shows the shape:
    `extern:wiz_array_empty:e:w:pure:::` — one erased type argument, then the array.
* `Wiz/Compiler/IRRun.lean` (`#run`): `IVal.arr`, recursive `dupV`/`dropV` over the
  elements (arrays are scalar values holding references, so the heap's RC must visit
  them), `toRVal`, and the same five operations in `nativeOp`. `push`/`set` copy:
  every element is `dup`ed into the new array, then the arguments are dropped, which is
  the reference-counting equivalent of the C runtime's in-place update when unique.
  The only place the copying model could be observed is C code that receives the
  buffer (`link_c`/`glue`) and mutates or aliases it; that code is compiled-only.
* `examples/array.wiz` (500 random `push`/`set`/`getD`/`size` operations, plus a
  persistence check) and `examples/array.expected`; one case in
  `Tests/Groups/Natives.lean` runs it through the existing `nativesSame` harness:
  `#eval`, `#run`, C and LLVM must all print the same number.

No `lib/*.wiz` file changed: the surface and the compiled path are untouched. That is the
point of option 5 — it buys the interpreter a real semantics without moving the
language or the runtime.

## 5. What remains for effects

* **The 99 effectful externs** (`Sys`, `MVar`, `Ref`, `Serial`, `Session`, `Handle`,
  `IO`) are not values: a pure table cannot give them semantics. `#eval` can build an
  `IO` action (it is a function over the linear world token) but cannot *run* it; the
  tests use `ioRun` and that is the correct boundary. Running an action needs a host
  event loop, real file descriptors, clocks and processes — option 4 can do that by
  compiling, but then elaboration performs effects, which is exactly what a checker
  must not do.
* **The remaining pure 28** (33 minus the 5 `Array` ops this prototype covers):
  `Str` 8 and `StrMap` 4 fit the same Lean bridge (`Str` is bytes in the runtime; the
  `BytesModel` string conversions are already there), `UInt64` 9 is Lean's `UInt64`,
  and `Float64` 7 is the hard one: round-to-nearest-even, subnormals, NaN payloads,
  signed zero, and `%.17g` formatting. A Lean `Float` model would need a differential
  test against C for each cell; the 50 `Float64` matrix cells are the ready-made suite.
* **Option 3** is the right end state for the pure remainder if the models should be
  visible to proofs and the kernel: make `Array`/`Str`/`StrMap` sealed inductives with
  native representations (as `WordArray`/`WordMap` already are) and let `#eval` ignore
  `implemented_by`, instead of adding a second, Lean-side model. The cost is the
  `Array` representation change (list conversions, or a new native representation), not
  the evaluator.
* **The differential obligation does not go away** in any option: a model (Wiz or Lean)
  is trusted to agree with `runtime/`. The `natives` group is the harness; the new
  `array` case is one line in it. `#print axioms` cannot list a Lean-side model, which
  is a reason to prefer option 3 once the surface types become inductives.
