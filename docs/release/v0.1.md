# Wiz 0.1 release notes (draft)

**Status: release candidate, not tagged.** These are the notes for `v0.1.0`, prepared
from `master` at commit `ed9cff34` (2026-11-14). No tag has been created and no release
has been published. Nothing here claims that a CI run, build or smoke test has passed:
the gates are in [v0.1-checklist.md](v0.1-checklist.md), and the machine-readable
release record is [release-manifest.json](release-manifest.json).

Wiz is a didactic dependently typed language: a quantitative type theory with
observational equality, an extensible elaborator, a compiler that targets C and LLVM,
a self-hosted toolchain, a build tool and a toolchain manager. It also describes and
simulates synchronous hardware, with proofs about specific circuits. The language and
its implementation are described in [docs/index.md](../index.md); this page is only
what 0.1 delivers.

## Headline features

### The language and the kernel

* A kernel for quantitative type theory, parametric in the rig (quantities `0`, `1`,
  `ω`), with universe polymorphism, `Σ`, `Unit`, `Empty`, and quantity polymorphism.
* Observational equality with an impredicative, proof-irrelevant `Prop`: function
  extensionality, `cast` that computes on data, and equality of descriptions that
  compares the codes.
* Data as indexed descriptions with `μ`/`ν`, `inductive` and `structure`, dependent
  pattern matching and structural recursion, sized types, codata and copatterns.
* **Mandatory sorts**: every `Π`/`Σ` carries its two component sorts and every `ULift`
  its content's sort, and the kernel checks each. This closes the unannotated-sort
  incompleteness and the subject-reduction gap around casts.
* **Proof markers (P2)**: both kernels suspend the proofs of `cast` and `transp` and
  require a verified marker wherever a proof would otherwise be evaluated. Proofs are
  not evaluated by the kernel. (The elaborator's own evaluation of terms it has not
  marked yet is bounded by a step budget; see the known limitations.)
* **Trusted evaluation and solvers, behind flags and off by default**: `native_refl`
  with `--trust-native` decides a closed equation by running both sides and records an
  axiom; `smt` with `--trust-smt` records an external solver's answer as an axiom (z3 by
  default; not bundled); `sat_decide` checks a CaDiCaL LRAT certificate with a checker
  written and proved sound in Wiz, adding no trust (CaDiCaL is in the release
  toolchain).
  `#print axioms` lists every axiom, native implementation and trust extension a
  declaration depends on.
* `castRefl` at propositions (PF-C), a second kernel written in Wiz
  (`selfhost/Kernel.wiz`), and WizMeta, a declarative specification and reference
  checker used as a third voter.
* Regularity is off by default; regularity at inert types is a conjecture (see
  [Status.md](../Status.md)). Several closed proofs of `False` found during development
  are fixed, each with a regression test.

### The language and the elaborator

* An extensible parser and an elaborator with implicit arguments and unification;
  macros by example, procedural macros and tactics written in Wiz; type classes with
  tabled resolution and `deriving`; instances and numeric classes
  (`Add`, `Sub`, `Mul`, `Div`, `Mod`, `Neg`, `OfNat`) with `Int`, `Rat` and `Nat`.
* Named arguments, private declarations and per-module privacy, structure patterns and
  structure update, `if`/`&&`/`||`/`!`, `∃` and ASCII logic, `let` tuple patterns,
  as-patterns, list literals, local notation, keyword scopes and `rfl` at a computed
  equation.
* Effects as a library with fusion and one-shot effects; linear types and borrowed
  handles; regions, with borrow checking as typing; sealed types; Feral, a Rust-like
  surface language as a command macro; and `deriving Lens`, which gives every field of a
  structure or a hardware bundle a lens.
* Separation logic: propositional logic over `Prop`, heaps and heap predicates, Hoare
  triples as a Dijkstra monad, and `x`-tactics. See
  [resources.md](../resources.md) and [stages/24-separation-logic.md](../stages/24-separation-logic.md).

### The self-hosted toolchain

* A lexer, parser, kernel, frontend and C backend written in Wiz (`selfhost/*.wiz`).
  The self-hosted frontend checks its own sources, and the bootstrap reaches a fixpoint:
  the stage-1 C generated by the Lean `wiz` and the stage-2 C generated by the
  self-hosted compiler are equal.
* Modules and imports (`-I`, a real module graph; stage 21y), constructor field
  quantities and implicit constructor fields (stage 21x), reference-counting and GC
  backends, a subset of the C FFI including `c_struct`, callbacks and `export`, and
  one-shot checker and compiler drivers.
* Parity with the Lean host is deliberately partial: the audited matrix is 27
  supported, 21 partial and 28 missing of 76 rows. The self-hosted toolchain is not yet
  a replacement for the Lean host: it cannot compile today's `lib/` and CLI. See
  "Self-hosted parity" in [Status.md](../Status.md).

### Running and compiling programs

* Erasure and an interpreter (`#eval`); an IR with Perceus reference counting and
  reuse; C and LLVM backends; unboxed structure fields and inlining.
* Machine integers, words and bit vectors, big numerals, and native structures: word
  arrays, word maps and interned strings (`lib/WordArray.wiz`, `lib/WordMap.wiz`,
  `lib/Intern.wiz`).
* A C FFI with header import, foreign pointers and finalisers, `link_c`/`link_lib`,
  callbacks and exported functions, C structs by value, and `lib/Sys.wiz` for
  processes, environment, files, bytes on handles, time limits and serial ports.
* Concurrency: a thread-safe runtime, session-typed linear channels, `MVar`s and
  locks (`lib/Session.wiz`, `lib/MVar.wiz`).
* `wiz build --split N` (opt-in, default 1) for parallel C compilation; it trades build
  time for a slower binary.

### HDL: circuits as ordinary programs

`lib/Hdl` is an embedded hardware description language: circuits are ordinary Wiz
programs, so one definition is a simulation model and a netlist for synthesis.

* A hash-consing netlist builder, named ports, registers, bundles with derived lenses,
  composition, reset and enable, operators, and Verilog emitters.
* Simulation, traces and the common `Trace`/`Mealy` semantics; memories; multi-clock
  domains; Xilinx 7-series constraints and the Arty A7; vendor primitives as black
  boxes.
* Temporal properties (`□`, `◇`, `○`, implications, fairness) and refinement; the
  iCEstick UART example with temporal properties.
* A verified circuit optimiser, bit-level laws by case split, and laws for memory reads
  and writes. These are proofs about specific circuits and libraries, not a theorem
  that the netlist, simulation and Verilog semantics agree for every circuit.

Start at [hardware.md](../hardware.md); the library sections are H14 in
[libraries.md](../libraries.md).

### Scry: not in this release

Scry, a static-analysis stack (WIL/CST, taint, points-to, Datalog, e-graph,
certificates, benchmark and SARIF), is **not on `master`** at this commit. Nothing in
0.1 provides a `scry` command or `lib/Scry`. Its memory model is a may-analysis even in
the in-flight design, so absence of a finding would not be a soundness claim. See
"Not in this release" below.

### Attestation: not in this release

There is no build attestation in 0.1: no TPM quote, no DSSE or in-toto statement, no
SLSA provenance, and no signed cache. The release assets and their SHA-256 checksums are
the whole record. A checksum detects a corrupted download; it does not attest who built
the artifact or from what source. E1 (a build manifest, a TPM quote and a signed
statement) is in flight and not on `master`; E2 (SEV-SNP) is design only. See the
attestation statement in the checklist.

### Tooling, LSP and build tools

* `wiz parse`, `check`, `build`, `run`, `lsp` and `doc`, with `--version`.
* A content-addressed elaboration cache shared between projects, with read-only layers.
* A language server: info tree, infoview protocol, code actions, go to definition,
  references, rename, semantic tokens, hovers, completion, signature help, inlay hints
  and workspace symbols; infoview clients in the terminal, in Neovim and in the browser
  (WebAssembly); a static playground.
* grail: modules by path, per-module cache keys, parallel jobs, git dependencies and
  `grail.lock`, command targets, `grail run`, `grail lsp` and `grail new`.
* tower: a toolchain manager in Wiz with `wiz`/`grail` shims, a `wiz-toolchain` file per
  project, a local override, release and snapshot installs, and channels (`stable`,
  `nightly`, tags, commits and `keep/…`).

## Install

The release is **x86_64 Linux only** for the prebuilt tarball: glibc 2.27 or later,
and glibc 2.30 or later for `wiz build` with the bundled C compiler (Ubuntu 20.04+,
Debian 11+, RHEL 9). Ubuntu 18.04 can check and run programs but not build them.

### tower, from the release tarball

After `v0.1.0` is tagged, the release carries `wiz-x86_64-linux.tar.gz` and its
`.sha256`. Install tower and make the release the default:

```sh
curl -sSfL https://raw.githubusercontent.com/wiz-pl/wiz/v0.1.0/scripts/tower-init.sh \
  | sh -s -- v0.1.0
export PATH="$HOME/.tower/bin:$PATH"
tower show        # v0.1.0
wiz --version     # wiz 0.1.0 (<commit>)
```

Until the tag exists, use `nightly` or a pinned snapshot instead of `v0.1.0`. A project
pins its toolchain in a `wiz-toolchain` file at its root:

```sh
echo v0.1.0 > wiz-toolchain
```

### Nix

```sh
# run without installing
nix run github:wiz-pl/wiz/v0.1.0#wiz -- check hello.wiz

# install tower and the wiz/grail shims
nix profile install github:wiz-pl/wiz/v0.1.0#tower

# Neovim with the Wiz plugin and this wiz on PATH
nix run github:wiz-pl/wiz/v0.1.0#nvim-wiz -- hello.wiz
```

The public Cachix cache is `badlydrawnwizards`; `cachix use badlydrawnwizards` once to
substitute instead of building. The flake also defines `packages.wiz`,
`packages.tower` and `packages.nvim-wiz` for `x86_64-linux` and `aarch64-linux`. Only
x86_64 release tarballs exist; aarch64 is a source/Nix build without a release promise.

### From source

```sh
git clone https://github.com/wiz-pl/wiz
cd wiz
nix develop                 # Lean, GMP, Boehm GC, LLVM and a C compiler
lake build wiz grail tower tests
```

Without Nix, use a Lean toolchain matching `lean-toolchain`, a C compiler and GMP; see
[building.md](../building.md). A checkout's `wiz` uses the system compiler and GMP
unless you pass `--cc`, `--cflags` and `--ldflags`.

### A first program

```sh
mkdir hello && cd hello
echo v0.1.0 > wiz-toolchain     # or `nightly` before the tag
cat > Main.wiz <<'EOF'
import IO
def main : IO Unit := IO.println "hello from Wiz"
EOF
wiz check Main.wiz
wiz run Main.wiz
wiz build Main.wiz -o hello && ./hello
```

For a package, a `grail.wiz` names its sources with the promised `Package` API (the
library and executable files are the ones the package already has; see the full example
in [install.md](../install.md)):

```wiz
import Grail
def package : Package := Package.new "hello"
  |> Package.lib "greet" "src"
  |> Package.exe "app" "App.wiz"
```

`grail build` and `grail run app` then build and run it. The full install guide,
including editor setup, is [install.md](../install.md).

## What 0.1 promises

The promises are deliberately few and are listed in [stability.md](../stability.md). A
patch release (0.1.0 → 0.1.1) keeps the `wiz-toolchain` file and tower's specs, release
tags and their download URLs, grail's documented `Package` API, and the `wiz` command
line without its experimental flags. Everything else, including the language, the
standard library, the LSP/infoview protocol and the C FFI ABI, is not promised and may
change in any 0.1.z release; a minor release (0.1 → 0.2) may break the promises too.
Breaks are listed in `CHANGELOG.md`. Snapshots, `nightly` and `master` promise nothing.
A closed proof of `False` with default flags is treated as a bug and will be fixed in a
patch release when the fix is known.

## Known limitations

These are the real limits of the candidate commit, not a list of everything unfinished.
[docs/Status.md](../Status.md) has the ledger, the tests that pin each item, and the
trusted base.

* **Nothing about Wiz as a whole is proved.** There is no model of the full calculus,
  no mechanised consistency or normalisation theorem, and no verified compiler. The
  ingredients have published metatheory for their own systems; their combination in Wiz
  has no published model. The trusted base is listed in Status §7.
* **Conjectures.** Regularity at inert types (D1) is a conjecture, argued relative to
  the regularity-off system; equality of descriptions, with `μ` injective in its
  description (E1), is a model obligation; propositions compared by equivalence and
  quantities in type equality are conjectures. `--regularity full` and other
  experimental flags are not covered by any claim.
* **The elaborator still evaluates some terms it has not marked** (P2-E, bounded by a
  step budget on read-back). The kernels do not evaluate proofs.
* **Open issues.** Σ unboxing is not stable under substitution, so `--unbox-structs`
  stays off by default (R3 open 1). Duplicating a `&mut` and borrowing one local twice
  in Feral are not rejected; both are pinned "KNOWN GAP" tests (wishful `linear-case`).
  WizMeta's specification is a conjecture, though it has had no disagreement with the
  kernel on its corpus.
* **Trust extensions are off by default.** `--trust-native` and `--trust-smt` each add
  an axiom per use, listed by `#print axioms`; they trust erasure, the interpreter,
  Lean's `Nat`, and the solver, as the stage docs say. The library never uses them.
* **The self-hosted toolchain is partial.** It checks its own sources and reaches a
  fixpoint, but it cannot yet compile the current `lib/` and CLI: modules are partial
  (`Prelude` is embedded and `IO`/`Std`/`Sys` are aliased), and classes, universe
  levels, the proof surface, named arguments, `deriving`, macros and tactics are missing
  from it. The full self-check case (`=selfhost#93`) needs more than 5 GB of memory, so
  it runs in CI rather than in a local run.
* **The release platform is x86_64 Linux.** The prebuilt toolchain needs glibc 2.27
  (2.30 for its bundled C compiler). There is no macOS or Windows release; other
  platforms work from source without a promise.
* **`--split` is opt-in** and defaults to 1; it is not used by CI or the fixpoint.
* **No package registry.** `master` has git dependencies and `grail.lock`, not a package
  index; registry signing is deferred.
* **The documentation site is the library API**, regenerated on every `master` push. It
  has no per-version switch; the user docs are the Markdown files in the repository at
  the tag.

## Licence

Wiz is GPL-3.0-or-later with the Wiz Runtime Library Exception for the runtime and the
libraries, so programs built with Wiz can carry their authors' licence. The release
tarball carries `LICENSE`, `COPYING.RUNTIME`, a `NOTICE` listing third-party code, and
the relevant licence texts. Programs built with the bundled C toolchain link GMP
statically; the `NOTICE` says what the LGPL asks when you distribute them. See
`LICENSE`, `COPYING.RUNTIME` and `scripts/release-licenses/NOTICE`.
