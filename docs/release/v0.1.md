# Wiz 0.1 release notes (draft)

**Status: release candidate, not tagged.** These are the notes for `v0.1.0`, prepared
from `master` at commit `4ad29792` (2026-11-18, the merge of #444). No tag has been
created and no release has been published. Nothing here claims that a CI run, build or
smoke test has passed: the gates are in [v0.1-checklist.md](v0.1-checklist.md), and the
machine-readable release record is [release-manifest.json](release-manifest.json).

Wiz is a didactic dependently typed language: a quantitative type theory with
observational equality, an extensible elaborator, a compiler that targets C, LLVM and
WebAssembly, a self-hosted toolchain, a build tool and a toolchain manager. It also
describes and simulates synchronous hardware, with proofs about specific circuits. The
language and its implementation are described in [docs/index.md](../index.md); this page
is only what 0.1 delivers.

## Summary

Wiz 0.1 is the first release candidate of a dependently typed language built around
quantitative type theory and observational equality. It has a Lean-hosted kernel and
elaborator, a self-hosted toolchain that reaches a three-stage bootstrap fixpoint, C,
LLVM and WebAssembly backends, an embedded hardware description language with proofs
about bus protocols, and Scry, a Wiz-hosted static-analysis package for C and C#. Since
the 2026-11-14 candidate, 141 merged pull requests (1,025 commits) added mandatory
sorts, inductive propositions, the self-hosted module loader, CLI and
tactic/derivation surface, the bus/protocol HDL stack, the Scry analysis stack, the
in-page playground language server, the Loom rename, the runtime/FFI hardening and the
CI reproducibility work. There is no earlier tag, so these notes cover the whole
repository history.

## Headline features

### The language and the kernel

* A kernel for quantitative type theory, parametric in the rig (quantities `0`, `1`,
  `ω`), with universe polymorphism, `Σ`, `Unit`, `Empty`, and quantity polymorphism.
* Observational equality with an impredicative, proof-irrelevant `Prop`: function
  extensionality, `cast` that computes on data, and equality of descriptions that
  compares the codes.
* Data as indexed descriptions with `μ`/`ν`, `inductive` and `structure`, dependent
  pattern matching and structural recursion, sized types, codata and copatterns.
* **Inductive propositions** (#252, #400): an inductive may live in `Prop`, with singleton
  elimination; large elimination from an inductive proposition is rejected.
* **Guarded descriptions and sized recursion**: a `μ` description is guarded and the size
  argument of `μ`/`ν` is checked (TT-06, #428); the shift operations are total for every
  `Nat` count (#343).
* **Mandatory sorts**: every `Π`/`Σ` carries its two component sorts and every `ULift`
  its content's sort, and the kernel checks each. This closes the unannotated-sort
  incompleteness and the subject-reduction gap around casts.
* **Proof markers (P2)**: both kernels suspend the proofs of `cast` and `transp` and
  require a verified marker wherever a proof would otherwise be evaluated. Proofs are
  not evaluated by the kernel. (The elaborator's own evaluation of terms it has not
  marked yet is bounded by a step budget; see the known limitations.)
* **Trusted evaluation and solvers, behind flags and off by default**: `native_refl`
  with `--trust-native` decides a closed equation by running both sides and records an
  axiom; `smt` with `--trust-smt` records an external solver's answer as an axiom (z3 by
  default; not bundled); `sat_decide` checks a CaDiCaL LRAT certificate with a checker
  written and proved sound in Wiz, adding no trust (CaDiCaL is in the release
  toolchain).
  `#print axioms` lists every axiom, native implementation and trust extension a
  declaration depends on.
* `castRefl` at propositions (PF-C), a second kernel written in Wiz
  (`selfhost/Kernel.wiz`), and WizMeta, a declarative specification and reference
  checker used as a third voter.
* Regularity is off by default; regularity at inert types is a conjecture (see
  [Status.md](../Status.md)). Several closed proofs of `False` found during development
  are fixed, each with a regression test.

### The language and the elaborator

* An extensible parser and an elaborator with implicit arguments and unification;
  macros by example, procedural macros and tactics written in Wiz; type classes with
  tabled resolution and `deriving`; instances and numeric classes
  (`Add`, `Sub`, `Mul`, `Div`, `Mod`, `Neg`, `OfNat`) with `Int`, `Rat` and `Nat`.
* Named arguments, private declarations and per-module privacy, structure patterns and
  structure update, `if`/`&&`/`||`/`!`, `∃` and ASCII logic, `let` tuple patterns,
  as-patterns, list literals, local notation, keyword scopes and `rfl` at a computed
  equation. Literal patterns (13q) match `Nat` numerals, strings and other literal
  types through `T.beq`; `calc` composes `=`, `≤` and `<` through `Trans` (13s), and the
  standard library uses it for the dense equality chains in `Nat`, `Ring` and `IntRing`.
* `deriving DecidableEq` (and the record update it pairs with, #345); `List` and
  `Boolean` lemmas and the simp normal forms that use them (#344, #359); a `Conc`
  effect over `Eff1` (#449).
* Effects as a library with fusion and one-shot effects; linear types and borrowed
  handles; regions, with borrow checking as typing; sealed types; Feral, a Rust-like
  surface language as a command macro; and `deriving Lens`, which gives every field of a
  structure or a hardware bundle a lens.
* Closing two elaborator holes: a private type can no longer be forged through a guessed
  hole solution (13b, #424), and a stuck equation against a data `Σ` is unified from the
  `Σ`'s stored sides (#392).
* Separation logic: propositional logic over `Prop`, heaps and heap predicates, Hoare
  triples as a Dijkstra monad, and `x`-tactics. See
  [resources.md](../resources.md) and [stages/24-separation-logic.md](../stages/24-separation-logic.md).

### The self-hosted toolchain

* A lexer, parser, kernel, frontend and C backend written in Wiz (`selfhost/*.wiz`).
  The parser tables are the checked-in `selfhost/Tables.wiz` (rendered from the Lean
  parser by `lake build genSelfhostTables`), and the entry points are
  `selfhost/Check.wiz` and `selfhost/Main.wiz`. The self-hosted frontend checks its own
  sources, and the bootstrap reaches a **three-stage fixpoint** by default: the stage-1
  C generated by the Lean `wiz`, the stage-2 C generated by the self-hosted compiler and
  the stage-3 C are byte-identical (`scripts/fixpoint.sh`; the scheduled CI job).
* Modules and imports (`-I`/`-IDIR`, `--include`, a real module graph and loader; stage
  21y, A14), constructor field quantities and implicit constructor fields (stage 21x),
  reference-counting and GC backends, a subset of the C FFI including `c_struct`,
  callbacks, `export` and `Bytes` (C11), and one-shot checker and compiler drivers.
* The self-hosted surface gained the features the library needs: notation, `syntax`,
  `macro_rules` and hygiene (A12), the tactic core (`by`, goal state, `intro`, `exact`,
  `apply`, `rw`, `calc`, `have`, `obtain`, …; A13), a deriver table with five built-in
  derivers (A11), polymorphic structures, two-level inductives and generic instances
  (U2b), and a host-vs-selfhost CLI differential (`=selfhost-cli-diff`) and library
  differential (`=selfhost-libdiff`).
* Parity with the Lean host is deliberately partial: the audited matrix is incomplete,
  and the bootstrap-critical rows are all supported or partial; the working ledger is
  `wiz-notes/selfhost-parity.md`. The self-hosted
  toolchain is not yet a replacement for the Lean host: it cannot compile today's `lib/`
  and CLI, and the library differential still measures prelude differences. See
  [Status.md](../Status.md) for the soundness ledger
  and [stages/30-selfhost-typeclasses.md](../stages/30-selfhost-typeclasses.md) for the
  type-class milestone.

### Running and compiling programs

* Erasure and an interpreter (`#eval`); an IR with Perceus reference counting and
  reuse; C and LLVM backends; unboxed structure fields and inlining.
* A **WebAssembly target** (8f): `wiz build FILE -o OUT --target wasm` emits a binary
  module from the IR, and `wiz run FILE --target wasm` runs it under Node. The subset
  covers IO-less `main`s over `Nat`/`Int`, constructors, closures, join points, codata
  and `Array`; the module is parsed and type-checked before it is written, and a
  reference-counted heap keeps a long-running program at its live-set peak. `--llvm` and
  `--wasm` remain aliases; limits are in [stages/08-backend/wasm.md](../stages/08-backend/wasm.md).
  Tail calls (`return_call`) and CAF caching are in (#372): a self tail call is a loop,
  and a closed definition is built once and shared.
* **Reproducible builds**: the same inputs give the same bytes from two absolute
  checkouts, and CI checks it. Cache entries use SHA-256 keys for manifests, regions and
  target/toolchain ids (#336, #337).
* Machine integers, words and bit vectors, big numerals, and native structures: word
  arrays, word maps and interned strings (`lib/WordArray.wiz`, `lib/WordMap.wiz`,
  `lib/Intern.wiz`). `UInt64.ofNat` is total (it reduces modulo 2⁶⁴ before the C call),
  `Float64.ofNat` rounds correctly for every `Nat`, and huge `Nat.pow`/`shiftLeft`
  results stay glued until needed (#343, #389).
* `lib/Plot.wiz` (#381) draws data plots as deterministic SVG over exact `Q`/`Int`
  arithmetic: `Plot.Frame` takes named `line`, `scatter`, `bar` and `step` series, four
  golden SVGs pin the output, and [libraries.md](../libraries.md) has the API.
* A C FFI with header import, foreign pointers and finalisers, `link_c`/`link_lib`,
  callbacks and exported functions, C structs by value, and `lib/Sys.wiz` for
  processes, environment, files, bytes on handles, time limits and serial ports.
* Concurrency: a thread-safe runtime, session-typed linear channels, `MVar`s and
  locks (`lib/Session.wiz`, `lib/MVar.wiz`); a `Conc` effect over `Eff1` (#449).
* `wiz repl` (11ac): one persistent frontend session with `:type`, `:load`, `:run`,
  `:reset`, `:help` and `:quit`, and `--prelude MODULE` to import a tool's prelude. The
  test wrapper is `wiz test-driver`; the single-file `wiz test FILE` is still a proposal.
* `wiz build --split N` (opt-in, default 1) for parallel C compilation; it trades build
  time for a slower binary.

### HDL: circuits as ordinary programs

`lib/Hdl` is an embedded hardware description language: circuits are ordinary Wiz
programs, so one definition is a simulation model and a netlist for synthesis.

* A hash-consing netlist builder, named ports, registers, bundles with derived lenses,
  composition, reset and enable, operators, and Verilog emitters. `match` on a signal is
  a case tree, not an elimination (#394).
* Simulation, traces and the common `Trace`/`Mealy` semantics; memories; multi-clock
  domains; Xilinx 7-series constraints and the Arty A7; vendor primitives as black
  boxes.
* The bus/protocol stack: an AMBA APB4 subset, classic Wishbone B4, AXI4-Lite, AXI4
  bursts (FIXED/INCR/WRAP, per-ID ordering), AXI4-Stream and SPI, with CRC-8/SMBUS and
  bridges between them. The modules are `lib/Hdl/{Bus,Apb,Wishbone,AxiLite,Axi4,AxiStream,Spi,Crc}.wiz`,
  with stability, response and strobe laws and the `bus-protocol`/`bus-crc` test groups
  (#346, #382). The superseded 2LTT staging plan is dropped (#368).
* Rune, a standard-library slice of simulated primitives (UART, SPI, DDR), and the
  iCEstick UART example with temporal properties.
* Temporal properties (`□`, `◇`, `○`, implications, fairness) and refinement.
* A verified circuit optimiser, bit-level laws by case split, and laws for memory reads
  and writes. These are proofs about specific circuits and libraries, not a theorem
  that the netlist, simulation and Verilog semantics agree for every circuit.

Start at [hardware.md](../hardware.md); the library sections are H14 in
[libraries.md](../libraries.md).

### Scry: static analysis written in Wiz

`scry/` is a grail package, not a `wiz` subcommand: build it with `grail build` and run
it as `grail run scry -- COMMAND`, from the `scry/` directory. The C frontend uses a
vendored tree-sitter; it spills a CST, lowers C to Wil, runs a flow-insensitive,
field-sensitive points-to analysis, then taint and findings. A C# frontend
(tree-sitter-c-sharp, fetched by Nix) lowers methods to Wil and has a CWE-78 taint rule.

The commands are `facts`, `query`, `explain`, `parse --stats`, `cst`, `taint`
(C → Wil → taint → findings/SARIF), `dynamic` (ASAN/UBSAN/coverage evidence),
`bench`, `project` (a `compile_commands.json` multi-file C project),
`report` (a self-contained HTML evidence page), `fuzz-span`, `findings`
(`scan`/`list`/`show`/`triage`/`repro`/`verify`) and `repl` (the Wiz REPL with
`Scry.Repl` preloaded). The `scry` test groups are `=scry-wil`, `=scry-c2wil`,
`=scry-csharp`, `=scry-ai`, `=scry-taint`, `=scry-uaf`, `=scry-workflow`,
`=scry-datalog`, `=scry-cert` and `=scry-egraph`.

The real-CVE corpus is opt-in: it is not part of `scry bench`, `grail test`, the fast
gate or CI, and no third-party source is checked in (each case pins its upstream
revision and fetches it into a cache). At this tree the checked-in table records
**0 of 6 in-scope CVEs detected**, so treat the synthetic corpus as a regression
baseline, not as real-world recall. Points-to is a may-analysis and the absence of a
finding is not a soundness claim; cross-file points-to and a single project-wide store
are not implemented. The C parse/lower pipeline also has a bounded fuzz campaign with
25 checked-in regression fixtures and its findings in `scry/bench/fuzz.md` (#478).
The package ships in the repository, not in the release tarball,
which carries the toolchain's `lib/` and binaries.

### SBOM, provenance and attestation

The release carries a CycloneDX 1.6 SBOM for the source tarball and for the binary
tarball, and `provenance.intoto.json`: an in-toto Statement v1 with the SLSA provenance
v1 predicate. The provenance records the release workflow and ref, the commit and source
tree, the Lean toolchain, the locked Nix and bundled C inputs, and the digest of every
asset. It is **SLSA-style**, not a hosted SLSA build: no SLSA level is claimed, and the
statement is an unsigned claim unless the release run had the E1 offline signing key
(`WIZ_ATTEST_KEY`), in which case a DSSE envelope and detached signature are assets too.
There is no TPM quote in the release path and no signed cache; E2 (SEV-SNP) is design
only. Checksums, an SBOM and provenance detect corruption and inventory the build; none
of them proves the builder was honest. See the supply-chain items in the checklist.

### Tooling, LSP and build tools

* `wiz parse`, `check`, `build`, `run`, `lsp`, `doc`, `fmt`, `repl` and `test-driver`,
  with `--version`. `wiz fmt` has `--check`, `--width N` and `--explain`; `wiz doc
  --reference` generates the reference manual and `--check` fails on a stale one, and
  `wiz doc --serve --lsp` serves live documentation.
* A content-addressed elaboration cache shared between projects, with read-only layers.
  Cache manifests, regions and target/toolchain ids use SHA-256 keys (#337).
* A language server: info tree, infoview protocol, code actions, go to definition,
  references, rename, semantic tokens, hovers, completion, signature help, inlay hints
  and workspace symbols; infoview clients in the terminal, in Neovim and in the browser
  (WebAssembly). The **playground's Goals pane is served in the page by default** by the
  self-hosted frontend compiled to Wasm (`web/selfhost-lsp-shim.js`), so diagnostics and
  `#check`/`#eval` need no server; `?lsp=ws://…` selects an external server, `?lsp=off`
  turns the pane off, and `?lsp=selfhost` names the in-page server explicitly. Plain goal
  and term-goal requests answer `null` until the expected-type index lands; the
  interactive methods answer `MethodNotFound`, so the pane uses its plain path.
  See [playground-lsp.md](../playground-lsp.md).
* grail: modules by path, per-module cache keys, parallel jobs, git dependencies and
  `grail.lock`, command targets, `grail run`, `grail lsp` and `grail new`; a static
  package registry with `grail update/fetch/publish`, lock v3, a content-addressed vendor
  store (`grail vendor`, `--vendor`), signed index snapshots and `grail index check`/
  `verify` (#360). Lock v1 and v2 still parse and `grail update` upgrades them. The root
  `grail test` run is green (88 passed, 0 failed, 2 skipped): `-- test: skip REASON` is a
  reported skip, and a subdirectory with its own `grail.wiz` is a nested package, not a
  test of the parent (#390).
* tower: a toolchain manager in Wiz with `wiz`/`grail` shims, a `wiz-toolchain` file per
  project, a local override, release and snapshot installs, and channels (`stable`,
  `nightly`, tags, commits and `keep/…`). The Lean reference implementation (`Tower/`,
  `tests --tower`) is removed; `tower/` is the only implementation.
* A stdlib-only MCP server (`tools/wiz-mcp`) for check, parse, fmt, build, diagnostics,
  hover, goals, navigation, completion, library search and docs, with path confinement
  and a stdio language server; a separate read-only Scry MCP server (`tools/scry-mcp`).
* A Jupyter kernel (`tools/jupyter`) with `%%scry`, `%%sh`, `%%time`, a progress channel
  and interactive notebook widgets, and a notebook exporter to self-contained HTML or
  Markdown with `--check`.

### CI and release engineering

* CI builds once with Nix, publishes to Cachix, and the shards consume the store
  (#329); `selfhost` and `library` are split by measured time and `selfhost-libdiff`
  checks files in parallel (#330, #471). A configuration that runs no test fails the
  run (#340), and a failed golden test's diff is the artifact (#367).
* The trust ledger is gated in the build job before any shard, with reasoned and
  reviewed rows (#335, #357, #440); the merge driver is three-way by key (#362, #414).
* Reproducibility from two absolute paths is a CI check (#336); nightly paired-ratio
  and peak-RSS gates cover the standard library and the Scry corpus (#358, #380, #396,
  #421). A failing shard is classified as flaky or deterministic, and the quarantine
  expires (#369).
* A merge queue is supported (`merge_group`).

## Install

The release is **x86_64 Linux only** for the prebuilt tarball: glibc 2.27 or later,
and glibc 2.30 or later for `wiz build` with the bundled C compiler (Ubuntu 20.04+,
Debian 11+, RHEL 9). Ubuntu 18.04 can check and run programs but not build them.

### tower, from the release tarball

After `v0.1.0` is tagged, the release carries `wiz-x86_64-linux.tar.gz` and its
`.sha256`. Install tower and make the release the default:

```sh
curl -sSfL https://raw.githubusercontent.com/wiz-pl/wiz/v0.1.0/scripts/tower-init.sh \
  | sh -s -- v0.1.0
export PATH="$HOME/.tower/bin:$PATH"
tower show        # v0.1.0
wiz --version     # wiz 0.1.0 (<commit>)
```

Until the tag exists, use `nightly` or a pinned snapshot instead of `v0.1.0`. A project
pins its toolchain in a `wiz-toolchain` file at its root:

```sh
echo v0.1.0 > wiz-toolchain
```

### Nix

```sh
# run without installing
nix run github:wiz-pl/wiz/v0.1.0#wiz -- check hello.wiz

# install tower and the wiz/grail shims
nix profile install github:wiz-pl/wiz/v0.1.0#tower

# Neovim with the Wiz plugin and this wiz on PATH
nix run github:wiz-pl/wiz/v0.1.0#nvim-wiz -- hello.wiz
```

The public Cachix cache is `badlydrawnwizards`; `cachix use badlydrawnwizards` once to
substitute instead of building. The flake also defines `packages.wiz`,
`packages.tower` and `packages.nvim-wiz` for `x86_64-linux` and `aarch64-linux`. Only
x86_64 release tarballs exist; aarch64 is a source/Nix build without a release promise.

### From source

```sh
git clone https://github.com/wiz-pl/wiz
cd wiz
nix develop                 # Lean, GMP, Boehm GC, LLVM and a C compiler
lake build wiz grail tower tests
```

Without Nix, use a Lean toolchain matching `lean-toolchain`, a C compiler and GMP; see
[building.md](../building.md). A checkout's `wiz` uses the system compiler and GMP
unless you pass `--cc`, `--cflags` and `--ldflags`.

### A first program

```sh
mkdir hello && cd hello
echo v0.1.0 > wiz-toolchain     # or `nightly` before the tag
cat > Main.wiz <<'EOF'
import IO
def main : IO Unit := IO.println "hello from Wiz"
EOF
wiz check Main.wiz
wiz run Main.wiz
wiz build Main.wiz -o hello && ./hello
```

For a package, a `grail.wiz` names its sources with the promised `Package` API (the
library and executable files are the ones the package already has; see the full example
in [install.md](../install.md)):

```wiz
import Grail
def package : Package := Package.new "hello"
  |> Package.lib "greet" "src"
  |> Package.exe "app" "App.wiz"
```

`grail build` and `grail run app` then build and run it. The full install guide,
including editor setup, is [install.md](../install.md).

## What 0.1 promises

The promises are deliberately few and are listed in [stability.md](../stability.md). A
patch release (0.1.0 → 0.1.1) keeps the `wiz-toolchain` file and tower's specs, release
tags and their download URLs, grail's documented `Package` API, and the `wiz` command
line without its experimental flags. Everything else, including the language, the
standard library, the LSP/infoview protocol and the C FFI ABI, is not promised and may
change in any 0.1.z release; a minor release (0.1 → 0.2) may break the promises too.
Breaks are listed under "Breaking changes" below and in `CHANGELOG.md`. Snapshots,
`nightly` and `master` promise nothing.
A closed proof of `False` with default flags is treated as a bug and will be fixed in a
patch release when the fix is known.

## Breaking changes

There is no earlier tag, so "breaking" means relative to a pre-release `master` checkout
or the 2026-11-14 candidate draft, not to a published release. The compatibility
promises are in [stability.md](../stability.md).

* **Renamed (source + JS host):** the UI framework is `Loom`, not `React` (#482).
  `lib/Web/React.wiz` is `lib/Web/Loom.wiz`, the module is `Web.Loom`, `React.*` is
  `Loom.*`, the Wasm exports are `wiz_loom_init`/`wiz_loom_html`/`wiz_loom_step`, and the
  test group is `loom`. There is **no compatibility alias**, and that is intended:
  nothing has been tagged yet, and a stale alias would keep two names alive. Update
  imports and the JS host; `Web.Widget`, `web/framework`, the Jupyter widget front end,
  examples and docs already use the new names (`docs/libraries.md:1538`).
* **Removed (source):** the Lean reference implementation of tower (`Tower/` and the
  test driver's `--tower` mode) is gone. `tower/` is the only implementation, and the
  `tower` test group tests it.
* **Renamed (CLI):** the test wrapper is `wiz test-driver`. `wiz test FILE` is a
  proposal, not a command; scripts that used the old wrapper name must change.
* **Changed (web):** the playground's default is the in-page language server. With no
  `lsp` parameter the pane is local; `?lsp=ws://…` selects an external server and
  `?lsp=off` disables it. A page that relied on "no server" as the default now runs the
  in-page one.
* **Changed (Scry):** a `compile_commands.json` is repository-supplied, so `scry project`
  and the MCP bridge refuse flags outside an explicit allowlist (#478). Keep `-I`,
  `-isystem`, `-iquote`, `-idirafter`, `-include`, `-D`, `-U` and `-std=`/`--std=`;
  `-B`, `-fplugin=`, `-specs=`, `-wrapper`, `@file`, `-Xclang` and `-cc1` are refused by
  name, and an uncurated CMake/Ninja database carrying `-O2`, `-g`, `-Wall`, `-fPIC`,
  `-x` or a compiler wrapper now fails with a diagnostic naming the flag
  (`scry/src/Scry/Project.wiz:17-25`, `tools/scry-mcp/scry_mcp.py:312-320`).
* **Changed (Scry MCP):** the bridge resolves `scry` only from `--scry`, `$SCRY_BIN` or
  `PATH`, never from the workspace's own `scry/.grail/bin/scry` (#487). That path is
  repository-controlled code; pass it explicitly if that is what you want.
* **Changed (runtime/FFI):** the eight boundary fixes of the 2026-11-17 review (9h/9k,
  #495). A failed `Process.exec` restores the caller's `SIGPIPE` disposition; `File.open`
  sets `FD_CLOEXEC`; `Fd.adopt` above `INT_MAX` is `EINVAL`; `IO.writeFile` prints
  `wiz: <path>: <message>` and exits 1 on a write failure (use `FS.writeBytes` for binary
  data); `FS.listDir` can fail where it used to return a short list; `Child.communicate`
  with input but no stdin pipe is `EBADF`; and `Child.releaseOwned`/`waitOwned` drain and
  discard output, so collect it with `Child.communicateOwned` first.
* **Changed (Wasm one-thread build):** a page built without `-pthread` now refuses to
  fork or block instead of hanging: the program stops with exit 3 and
  `wiz: <what>: threads are not available in this build (WIZ_NO_THREADS)` (#488, #489).
* **Changed (self-hosted build):** the entry points are `selfhost/Check.wiz` and
  `selfhost/Main.wiz`; the parser tables are the checked-in `selfhost/Tables.wiz`,
  rendered by `lake build genSelfhostTables`. The generated table source that used to
  live under `web/` is gone.
* **Compatible format change:** `grail.lock` v3 adds a toolchain, size/tree/command
  digests and a sorted dependency list. v1 and v2 locks still parse and `grail update`
  upgrades them; the index and lock formats are otherwise unchanged.

## Known limitations

These are the real limits of the candidate commit, not a list of everything unfinished.
[docs/Status.md](../Status.md) has the ledger, the tests that pin each item, and the
trusted base.

* **Nothing about Wiz as a whole is proved.** There is no model of the full calculus,
  no mechanised consistency or normalisation theorem, and no verified compiler. The
  ingredients have published metatheory for their own systems; their combination in Wiz
  has no published model. The trusted base is listed in Status §7.
* **Conjectures.** Regularity at inert types (D1) is a conjecture, argued relative to
  the regularity-off system; equality of descriptions, with `μ` injective in its
  description (E1), is a model obligation; propositions compared by equivalence and
  quantities in type equality are conjectures. `--regularity full` and other
  experimental flags are not covered by any claim.
* **The elaborator still evaluates some terms it has not marked** (P2-E, bounded by a
  step budget on read-back). The kernels do not evaluate proofs.
* **Open issues.** Σ unboxing is not stable under substitution, so `--unbox-structs`
  stays off by default (R3 open 1). Duplicating a `&mut` and borrowing one local twice
  in Feral are not rejected; both are pinned "KNOWN GAP" tests (wishful `linear-case`).
  WizMeta's specification is a conjecture, though it has had no disagreement with the
  kernel on its corpus.
* **Trust extensions are off by default.** `--trust-native` and `--trust-smt` each add
  an axiom per use, listed by `#print axioms`; they trust erasure, the interpreter,
  Lean's `Nat`, and the solver, as the stage docs say. The library never uses them.
* **The self-hosted toolchain is partial.** It checks its own sources and reaches a
  three-stage fixpoint, but it cannot yet compile the current `lib/` and CLI. The audited
  matrix is incomplete, with the bootstrap-critical rows supported or partial
  (`wiz-notes/selfhost-parity.md`); A11 derivers, A12
  notation/macros, A13 tactics, A14 modules and U2b are in, while the type-class
  milestone (A10) is still a subset and the library differential measures prelude
  differences. The full self-check case needs more memory than a small local run, so it
  runs in CI rather than in a local run.
* **Scry is a may-analysis.** Its points-to and taint are not a soundness claim: an
  absent finding does not prove absence, the real-CVE corpus detects 0 of 6 in-scope
  CVEs at this tree, and cross-file points-to and a single project-wide store are not
  implemented.
* **STC is a specification, not a model.** `STC/F0` states the F0 judgments and rules in
  Lean and proves the renaming and substitution lemmas; soundness, consistency,
  weak-head normalisation and decidability are `Prop`s in `STC/F0/Obligations.lean`. It
  is not a default Lake target and nothing imports it. The M0.0 triage (no Abel–Coquand
  loop in either kernel; the sized-type `∞ < ∞` acceptance is fixed) is a separate,
  unmerged pass, and its regression test is not in this tree.
* **The playground's plain goal requests are empty.** The in-page server answers
  diagnostics and `#check`/`#eval`, but `wiz/plainGoal` and `wiz/plainTermGoal` return
  `null` until the expected-type index lands, and the interactive methods are
  `MethodNotFound`. The pane falls back to its plain path; an external server can fill
  it.
* **The release platform is x86_64 Linux.** The prebuilt toolchain needs glibc 2.27
  (2.30 for its bundled C compiler). There is no macOS or Windows release; other
  platforms work from source without a promise.
* **`--split` is opt-in** and defaults to 1; it is not used by CI or the fixpoint.
* **The registry is static and has no transparency log.** `grail` has a package index,
  lock v3, signed index snapshots and a vendor store, but no TUF/Sigsum transparency
  log, key rotation, or index-hosted provenance; the static registry is not a safety
  claim.
* **The documentation site has no per-version switch.** It is regenerated on every
  `master` push (API, docs, playground and benchmark pages); the user docs are the
  Markdown files in the repository at the tag.
