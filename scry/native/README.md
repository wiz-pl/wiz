# tree-sitter (native parser)

scry parses C and C# with [tree-sitter](https://tree-sitter.github.io/) through one C
shim, `ts_shim.c` (design §4.1; `scry_parse` takes the language, `"c"` or `"c_sharp"`).
`link_c` compiles the sources with the program (Wiz has no `link_pkg`). The runtime is
vendored here; both grammars are fetched by Nix, because their `src/parser.c` files
(3.9 MB and 29.7 MB) are generated by tree-sitter and generated files are not committed.

| source | version | commit | provided by |
|---|---|---|---|
| [tree-sitter](https://github.com/tree-sitter/tree-sitter) | v0.27.2 | `3fb7be49145acfb07e33b61ed5689e2b6771b2e9` | vendored, `tree-sitter/` |
| [tree-sitter-c](https://github.com/tree-sitter/tree-sitter-c) | v0.24.2 | `b780e47fc780ddc8da13afa35a3f4ed5c157823d` | Nix, `.#tree-sitter-c` |
| [tree-sitter-c-sharp](https://github.com/tree-sitter/tree-sitter-c-sharp) | v0.23.5 | `cac6d5fb595f5811a076336682d5d595ac1c9e85` | Nix, `.#tree-sitter-c-sharp` |

All three are MIT licensed. The runtime's licence text is `tree-sitter/LICENSE`; each
grammar's is in its fetched tree and copied below. Each grammar's `src/parser.c` is the
upstream generated file, not regenerated here (`LANGUAGE_VERSION 15`, which is the ABI
this runtime implements).

## The grammar out-links

To compile scry's native code (`grail build`, `grail test`, `wiz build
tools/CstMain.wiz`, `fuzz/run.py`, `scripts/real-corpus.sh`, …), make the out-links once
per checkout, and again after a pin changes:

```sh
scry/native/link-grammars.sh
```

It runs, from the repository root,

```sh
nix build .#tree-sitter-c       -o scry/native/tree-sitter-c
nix build .#tree-sitter-c-sharp -o scry/native/tree-sitter-c-sharp
```

Each is then a symlink into the store (and a GC root), and both are gitignored. The
`link_c` paths in `src/Scry/Native.wiz` go through them unchanged. Without them, `wiz
check` of `src/Scry/Native.wiz` reports `link_c: no file
../../native/tree-sitter-c/src/parser.c` (or the C# one). The Lean test groups don't
need them: they read checked-in spills (`corpus/**/*.cst`).

## Bumping a pin

The grammars are `fetchFromGitHub` derivations in `flake.nix`, each pinned by a commit
(`rev`) and the NAR hash of the unpacked tree (`hash`). To move one to a new release:

1. find the release's commit: `git ls-remote https://github.com/tree-sitter/tree-sitter-c
   'refs/tags/v0.X.Y*'` (the `^{}` line is the commit an annotated tag points to);
2. get its hash: `nix flake prefetch --json github:tree-sitter/tree-sitter-c/<commit>`
   prints it as `"hash"` (or set `hash = "";`, run `nix build .#tree-sitter-c`, and copy
   the `got:` hash from the mismatch error);
3. set `rev` (with the tag in its comment) and `hash` in `flake.nix`, and update the
   table above and the grammar's section below;
4. check the generated parser's ABI: `grep LANGUAGE_VERSION
   scry/native/tree-sitter-c/src/parser.c` must be one the vendored runtime accepts
   (`TREE_SITTER_MIN_COMPATIBLE_LANGUAGE_VERSION` … `TREE_SITTER_LANGUAGE_VERSION` in
   `tree-sitter/lib/include/tree_sitter/api.h`);
5. rerun `scry/native/link-grammars.sh`, `nix build .#scry-native` (its check parses one
   file per grammar), and the tests that read the grammar (`grail test` in `scry/` for
   the native C path; for C, also regenerate the checked-in `.cst` spills and the
   `grammars/tree-sitter-c/node-types.json` excerpt if node kinds changed, and review
   the diff: a changed tree is a changed output);
6. push the new `.#tree-sitter-c`/`.#scry-native` outputs to Cachix (ask main).

The same steps apply to tree-sitter-c-sharp (repository `tree-sitter-c-sharp`, attribute
`.#tree-sitter-c-sharp`).

## Layout

```
native/
├── ts_shim.c                     the one C entry point (scry_parse + column accessors)
├── tree-sitter/
│   ├── LICENSE
│   └── lib/
│       ├── include/tree_sitter/api.h        the public runtime API
│       └── src/                             runtime sources; lib.c includes them all
├── link-grammars.sh              makes the two grammar out-links below
├── tree-sitter-c -> /nix/store/…-source         uncommitted out-link (above)
└── tree-sitter-c-sharp -> /nix/store/…-source   uncommitted out-link (above)
```

Two include-path adjustments are local to the vendored runtime (no source change); they let
`link_c` compile the files without `-I` flags:

* `tree-sitter/lib/src/tree_sitter/api.h` forwards to
  `../../include/tree_sitter/api.h` (the runtime sources include
  `"tree_sitter/api.h"`);
* `tree-sitter/lib/src/unicode/unicode/*.h` forward to the headers one level up (the
  Unicode headers include each other as `"unicode/…"`).

Everything else is the upstream files: `tree-sitter/lib/src/lib.c`, both `parser.c`
files and tree-sitter-c-sharp's `src/scanner.c` are compiled as they are, at the versions
above (each grammar's `src/` holds its own `tree_sitter/parser.h`, so the two never mix).

## Build

`src/Scry/Native.wiz` has

```wiz
link_c "../../native/ts_shim.c"
link_c "../../native/tree-sitter/lib/src/lib.c"
link_c "../../native/tree-sitter-c/src/parser.c"
link_c "../../native/tree-sitter-c-sharp/src/parser.c"
link_c "../../native/tree-sitter-c-sharp/src/scanner.c"
```

grail compiles the `link_c` files with the same compiler and cflags as the program and
keys the link job by their paths and contents. `wiz check` only checks that the files
exist; the C compiler runs on `wiz build`/`wiz run` and on grail's link job.

The shim uses the runtime's C interface for word arrays (`wiz_warray_of_c`, see
`docs/stages/29-natives.md`): a column is copied into an owned `U32Array`/`U64Array`,
and no C struct crosses the FFI by value.
